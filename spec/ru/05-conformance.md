# Соответствие (conformance)

## Уровни

### L1 — Type-aware payload

Устройство или сервис:

1. Использует только зарегистрированные `std:` type id (или явно объявляет расширение `x:` — вне scope v0.1).
2. Указывает `unit` и `enc`, совместимые с карточкой типа.
3. Для quantity соблюдает диапазон карточки, если он задан.

### L2 — Profile conformance

Устройство:

1. Заявляет один или несколько профилей из `registry/profiles/`.
2. Обязательно публикует все `required` типы профиля.
3. Может публиковать `optional` типы профиля и любые другие зарегистрированные типы.

### L3 — Tooling conformance

Инструмент (валидатор, codegen, SDK):

1. Читает YAML-реестр согласно JSON Schema в `schema/`.
2. Отклоняет неизвестные kind/domain/encoding.
3. Не переиспользует deprecated id как новые.

## Заявление соответствия

Производитель может указать в документации:

```
STANDART 0.1 — L2 — profile: thermometer
```

## Проверка

```bash
node tools/validate.mjs
```

Успешный выход (код 0) означает, что реестр и профили согласованы со схемой.

## Вне scope

- Криптографическая аттестация устройств.
- Сертификация лабораториями.
- Соответствие транспортным протоколам.
